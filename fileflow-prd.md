# FileFlow — Product Requirements Document

## Overview

FileFlow is a lightweight, native file organization daemon for Windows. It monitors designated folders (Downloads, Desktop) and automatically moves files to their correct destination on W:\ based on a layered rule system. Written in Rust, compiled to a single `.exe`, zero dependencies at runtime.

---

## Problem

Files accumulate in Downloads and Desktop. Manual organization is tedious and inconsistent. Existing tools (DropIt, etc.) are clunky, poorly configurable, and don't handle edge cases like in-progress downloads.

## Solution

A background service that watches folders and routes files using a predictable, layered rule system. No GUI needed for core functionality — configured via a single YAML/TOML config file.

---

## Architecture

```
fileflow.exe
├── Watcher       ← monitors folders using Windows ReadDirectoryChangesW API
├── Classifier    ← applies rules in priority order
├── Mover         ← moves files safely (waits for locks, handles duplicates)
├── Config        ← reads/reloads config file
└── Logger        ← logs all actions to file + optional system tray notifications
```

### Single Binary

- No installer needed
- Runs from any location
- Can be added to Windows startup via registry or Task Scheduler

## Core Features

### 1. Folder Monitoring

- Watch multiple folders simultaneously
- Use Windows native `ReadDirectoryChangesW` (not polling)
- React to: file created, file renamed (download complete changes `.crdownload` → `.pdf`)
- Configurable via config file:

```toml
[watch]
paths = [
  "C:\\Users\\%USERNAME%\\Downloads",
  "C:\\Users\\%USERNAME%\\Desktop"
]
```

### 2. Smart File Detection (Skip In-Progress Downloads)

**Critical feature.** Files must not be moved while still downloading.

Strategy:
1. **Extension blocklist** — ignore files with temp extensions:
   - `.tmp`, `.crdownload` (Chrome), `.part` (Firefox), `.partial`, `.download`, `.opdownload` (Opera)
2. **File lock check** — before moving, attempt to open file with exclusive access. If locked, skip and retry later.
3. **Stability delay** — after detecting a new file, wait N seconds (configurable, default: 3) and check if file size is still changing. Only move when stable.
4. **Rename detection** — when `.crdownload` is renamed to `.pdf`, treat it as a new file event and classify.

```toml
[safety]
ignore_extensions = [".tmp", ".crdownload", ".part", ".partial", ".download", ".opdownload"]
stability_delay_seconds = 3
retry_interval_seconds = 10
max_retries = 30
```

### 3. Layered Classification System

Rules are applied in strict priority order. First match wins.

#### Layer 1: Filename Patterns → Direct Target

Patterns generated by programs/devices. High confidence.

| Patterns | Destination |
|----------|-------------|
| `Screenshot*`, `Screen Shot*`, `Ekran görüntüsü*`, `Clipboard*`, `Snipaste*`, `ShareX*`, `Lightshot*`, `Greenshot*` | `W:\Media\Screenshots\` |
| `IMG_*`, `DSC_*`, `DCIM*`, `PXL_*`, `DSCF*`, `Photo*` | `W:\Media\Images\` |

#### Layer 2: Extension → Direct Target

Extensions that always mean the same thing.

| Extensions | Destination |
|------------|-------------|
| `.fig`, `.xd`, `.sketch`, `.psd`, `.ai`, `.indd`, `.afdesign`, `.afphoto` | `W:\Design\` |
| `.mp4`, `.mov`, `.avi`, `.mkv`, `.webm`, `.flv`, `.wmv`, `.m4v` | `W:\Media\Videos\` |
| `.mp3`, `.wav`, `.flac`, `.aac`, `.ogg`, `.m4a`, `.wma` | `W:\Media\Audio\` |
| `.jpg`, `.jpeg`, `.png`, `.gif`, `.webp`, `.bmp`, `.tiff`, `.svg`, `.ico`, `.raw`, `.cr2`, `.nef` | `W:\Media\Images\` |

#### Layer 3: Extension → Downloads Subfolders

Purpose ambiguous, type clear.

| Extensions | Destination |
|------------|-------------|
| `.pdf`, `.doc`, `.docx`, `.xls`, `.xlsx`, `.ppt`, `.pptx`, `.odt`, `.ods`, `.txt`, `.rtf`, `.csv` | `W:\Downloads\Documents\` |
| `.zip`, `.rar`, `.7z`, `.tar`, `.gz`, `.bz2` | `W:\Downloads\Archives\` |
| `.js`, `.ts`, `.py`, `.html`, `.css`, `.json`, `.yaml`, `.yml`, `.xml`, `.sql`, `.sh`, `.bat`, `.ps1`, `.rb`, `.go`, `.rs`, `.java`, `.c`, `.cpp`, `.h`, `.php`, `.swift`, `.kt`, `.lua`, `.r`, `.md` | `W:\Downloads\Code\` |
| `.ttf`, `.otf`, `.woff`, `.woff2`, `.eot` | `W:\Downloads\Fonts\` |
| `.exe`, `.msi`, `.appx`, `.msix`, `.iso`, `.img` | `W:\Downloads\Setup\` |

#### Layer 4: Fallback

Unmatched files stay in place. No action. They are **not moved** — this prevents accidental relocation of unknown file types.

### 4. Safe File Moving

- **Duplicate handling**: if destination has same filename, append `_1`, `_2`, etc. before extension
- **Atomic move**: use `rename` when same drive, `copy + delete` when cross-drive
- **Permission check**: verify write access to destination before attempting move
- **Create directories**: auto-create destination folder if it doesn't exist

### 5. Logging

All actions logged to `fileflow.log` in the app directory.

Format:
```
[2026-03-08 14:23:01] MOVED screenshot_2026.png → W:\Media\Screenshots\ (rule: filename_pattern)
[2026-03-08 14:23:05] SKIPPED report.crdownload (reason: temp_extension)
[2026-03-08 14:23:10] SKIPPED unknown.xyz (reason: no_matching_rule)
[2026-03-08 14:25:00] RETRY budget.xlsx (reason: file_locked, attempt: 2/30)
```

```toml
[logging]
path = "fileflow.log"
max_size_mb = 10
rotate = true
```

### 6. System Tray (Optional, Phase 2)

- Tray icon showing status (watching / paused / error)
- Right-click menu: Pause, Resume, Open Log, Open Config, Quit
- Toast notifications for moved files (optional, off by default)

```toml
[notifications]
enabled = false
```

## Config File

Single TOML file: `fileflow.toml` (next to the .exe)

Full example:

```toml
[watch]
paths = [
  "C:\\Users\\sina\\Downloads",
  "C:\\Users\\sina\\Desktop"
]

[safety]
ignore_extensions = [".tmp", ".crdownload", ".part", ".partial", ".download", ".opdownload"]
stability_delay_seconds = 3
retry_interval_seconds = 10
max_retries = 30

[logging]
path = "fileflow.log"
max_size_mb = 10
rotate = true

[notifications]
enabled = false

# --- Rules ---
# Rules are evaluated top to bottom. First match wins.

[[rules]]
```

## Rust Crates (Recommended)

| Crate | Purpose |
|-------|---------|
| `notify` | Cross-platform filesystem watcher (uses ReadDirectoryChangesW on Windows) |
| `toml` + `serde` | Config parsing |
| `glob` | Filename pattern matching |
| `log` + `env_logger` or `tracing` | Logging |
| `windows-sys` | Windows API for file lock checks |
| `tray-item` or `tao` + `winit` | System tray (Phase 2) |
| `clap` | CLI args (--config, --dry-run, --install) |

---

## CLI Interface

```bash
# Run in foreground (for testing)
fileflow.exe

# Run with custom config
fileflow.exe --config path/to/fileflow.toml

# Dry run — log what would happen without moving
fileflow.exe --dry-run

# Install as Windows startup task
fileflow.exe --install

# Uninstall from startup
fileflow.exe --uninstall

# Process existing files in watched folders once, then exit
fileflow.exe --scan-once

# Create default config file
fileflow.exe --init
```

## Phases

### Phase 1 — Core (MVP)
- Folder watching with `notify` crate
- Layered classification (pattern + extension)
- Safe file moving with lock check + stability delay
- Skip in-progress downloads
- TOML config
- File logging
- CLI: `--config`, `--dry-run`, `--scan-once`, `--init`

### Phase 2 — Polish
- System tray icon + controls
- Toast notifications
- `--install` / `--uninstall` (Windows startup)
- Log rotation
- Hot-reload config (watch `fileflow.toml` for changes)

### Phase 3 — Advanced (Future)
- Prefix system for manual routing (`kf_`, `ef_`, etc.)
- Project-aware routing (integrate with project CLI)
- Age-based auto-archive (30 day → Archive folder)
- Stats dashboard (how many files moved, where, when)

---

## Non-Goals

- No GUI for rule management (config file is enough)
- No cloud sync
- No file content analysis
- No rename/transform logic (files keep their original names)
- No delete functionality (only move)
